## The 8-port patch is REAL (corrected finding)

First pass claimed "config-only, no patches" — **wrong**, caused by reading
`pacman -Qkk` through `2>/dev/null` (warnings go to stderr). The live box runs
`/root/bliswitch/install-bliswitch-v2.sh`, which patches
`kvmd/plugins/ugpio/xh_hk4401.py` via `patch-xh_hk4401-8port.py` (driver
backup kept next to it). The patch is 3 lines:

1. `valid_number.mk(min=0, max=3, ...)` → `max=7` (pin validator)
2. RX regex `G0[1-4]` → `G0[1-8]` (both protocol framings, one line)
3. `assert 0 <= channel <= 3` → `<= 7` (TX)

kvmd 4.217 (hatch01) carries the identical stock strings → the same patch
applies. Implemented as `overrideAttrs`/`postPatch`/`substituteInPlace`
(`--replace-fail`, so drift fails loudly).

## OTG: hatch01 DOES cover it (corrected finding)

`modules/kvmd.nix` (hatch01) includes `kvmd-otg.service` (+otgnet, ipmi,
janus, media, pst, vnc, oled, tc358743 EDID loader, msd-image, htpasswd),
kernel modules (`dwc2 libcomposite configfs usb_f_ecm tc358743`), all kvmd
sub-users, sudo helper rules, msd/pst filesystems. Earlier "OTG is missing"
was from reading only the module head.

**Real bug found & fixed**: hatch01 ships its `dtoverlay=` entries as
`boot.kernelParams` — cmdline.txt — which the Pi firmware ignores. Verified by
eval: config.txt had no dwc2/tc358743 at all. Fixed via the config.txt API:
hatch01's own `deviceTreeOverlays.pi4 = dwc2 peripheral` now actually lands
(present exactly once in the evaluated overlays), and capture uses
`hardware.raspberry-pi."4".tc358743.enable`. Still to verify on real boot:
`disable-bt` (settings.all.dtoverlay), and that the tc358743 dtbo reaches the
firmware partition.

## Architecture (modular, multi-host)

- `modules/nixos/hosts/pikvm/default.nix` — **inert**: snowfall auto-imports
  every `modules/nixos/**/default.nix` into ALL hosts, so this must stay
  option-free (an auto-global module setting `services.kvmd.*` or
  `hardware.raspberry-pi.*` breaks every host lacking those options — proven
  by astrolabe eval failure).
- `modules/nixos/hosts/pikvm/host.nix` — **the reusable module**, explicitly
  imported by each PiKVM host. Declares `projectinitiative.hosts.pikvm.*`:
  - `enable`, `hardwareVersion` (default `v3-hdmi-rpi4`)
  - `bliSwitch8Port.{enable, device}` — the toggle: patched kvmd package +
    gpio scheme + view table + /dev/bliswitch udev rule
  - base config.txt fixes for every PiKVM host (OTG/capture)
- Host (`systems/aarch64-linux/pikvm/`): imports hatch01 + host.nix, sets the
  toggle; keeps only host-specific identity/network/ssh/udev-serials.

Future plain PiKVM host = import hatch01 + host.nix, set `enable = true`
(and no `bliSwitch8Port`). Future 8-port host = also flip the toggle.

## Gotchas log

1. **Dirty git tree hides untracked files** from nix eval — `git add -A` first.
2. **Two `${namespace}.` top-level attrs in one file are illegal** — merge.
3. **`modules/nixos/**/default.nix` is auto-global** — never set options there
   that don't exist on every host; keep reusable modules as non-`default.nix`
   siblings imported explicitly.
4. **`pacman -Qkk` warnings go to stderr** — `2>/dev/null` silently hides
   "altered file" evidence. (This caused the wrong "no patches" conclusion.)
5. **`dtoverlay=` in `boot.kernelParams` is dead config** on Pi — firmware
   reads config.txt only.
